# Frontier menu and ranking

New installations and installations with only the old difficulty preference start on Hardcore, the existing hardest mode. Explicit subsequent choices are persisted under sunset_difficulty_v2. Combat multipliers are unchanged. Changing difficulty from the paused menu updates the active run's damage/spawn calculations and restart configuration; existing enemies retain their current health.

The title keeps PRESS START and one auxiliary MENU button. A separate MenuScene overlays and pauses its owner. Audio, difficulty, controls, ranking, statistics and unlockables are launched as nested pages; closing a page resumes the same menu, and closing that menu resumes its owner. The game stays paused until CONTINUE or Escape on the pause screen. Localhost developer access remains in the menu and on F2.

The death screen has a large native name input with a bright yellow caret, autofocus and mobile keyboard support. Input events stay inside the field, including Enter to submit; Escape releases text focus. A submitted name is normalized to at most 18 characters. Submitting the death result stops the death scene and removes its native input. BACK from that ranking goes directly to the title in one step; ranking opened from MENU returns to that same menu. Retrying or returning to title also saves an entered name. Empty names are not saved, but the ranking remains viewable. Real zero kills, bounty and time are retained.

Ranking now uses a server API with a local cache and durable pending-submission queue. SQLite serves localhost; static production builds can point to the Cloudflare Worker/D1 endpoint using VITE_RANKING_API_URL. Existing local results migrate once. Failed writes stay queued and retry on ranking refresh, new submissions or reconnect. The top 100 named runs are sorted by the existing score formula (gold × 10 + kills × 50), with stage, kills, survival time and ID as tie breakers. Rows show stage and difficulty, seven per page. Server writes are idempotent by run ID and recalculate score. See ranking-server.md for persistence, deployment and backup instructions.

HOW TO PLAY and STATS reuse the approved Billy poster, proportionally fitted rather than enlarging the gameplay sprite. Unlockables use standalone posters without individual wood/parchment boxes or a large wood backing. Posters now fit up to 260 logical pixels high (previously 178), with separate captions and intact tab/unlock rules. Offline art scale comparison: ../art-direction/menu-poster-comparison.png and its JSON measurement report; this is not a runtime screenshot.

Automated checks cover persistence, storage failure, bounded ranking pages, duplicate submission, zero-valued death results, keyboard isolation/IME and input cleanup, menu ownership and return paths, paused difficulty changes, sound controls, uniform portrait scaling and the removal of poster wrappers. No browser gameplay or screenshots are used to validate rules.
